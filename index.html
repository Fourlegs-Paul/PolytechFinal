UI 클릭 → 요청 → API Route → 외부 서비스/DB → 응답 → 화면 표시 순서로 추적해줘. 추측하지 말고 각 단계의 실제 로그와 상태 코드로 첫 실패 지점을 찾아줘.
04 · VERIFY

완료 보고를 증거로 바꾸기

수정 결과를 실제로 검증해줘. 변경 파일, 실행·빌드 결과, 브라우저 오류, 모바일 화면, 남은 문제를 확인한 사실과 함께 보고하고 관련 MD만 갱신해줘.
401 / 403

인증 또는 권한

키·토큰 전달 위치, 만료, Scope, RLS 정책과 서버/브라우저 키 구분을 확인합니다.

CORS

브라우저 호출 차단

외부 API를 브라우저에서 직접 부르지 말고 앱의 서버 Route를 통해 호출합니다.

404

주소 또는 Route

Base URL, endpoint path, HTTP Method, 배포 환경의 Root Directory를 확인합니다.

429

요청 한도

Quota와 Rate Limit을 확인하고 캐시, 지수 백오프, 재시도 제한을 설계합니다.

OAUTH LOOP

로그인이 계속 돌아옴

Redirect URI의 철자·프로토콜·도메인과 Supabase Allow List를 정확히 맞춥니다.

BUILD FAIL

로컬은 되는데 배포 실패

대소문자 경로, 누락된 환경변수, Node 버전, 의존성 lockfile과 Build Logs를 봅니다.

EMPTY DATA

성공인데 데이터가 없음

응답 JSON의 실제 중첩 구조, query parameter, 사용자 ID와 RLS 필터를 확인합니다.

SECRET LEAK

키를 Git에 올림

파일 삭제로 끝내지 말고 즉시 키를 폐기·재발급한 뒤 Git 기록과 배포 환경을 점검합니다.
