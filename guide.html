SOCIAL LOGIN

Google OAuth 연결하기

Console 열기 ↗

→
2 · SUPABASEGoogle로 이동

3 · GOOGLE사용자 동의

4 · CALLBACK세션 발급
  1. 01

    Cloud 프로젝트 생성

    Google Cloud Console 상단의 프로젝트 선택기에서 New Project를 선택해 프로젝트를 만들고 활성 프로젝트로 지정합니다.

  2. 02

    Google Auth Platform 시작

    Branding에서 앱 이름·지원 이메일을, Audience에서 Internal/External을 설정합니다. 수업 테스트라면 External + Test users에 본인 이메일을 등록합니다.

  3. 03

    최소 Scope 선택

    Data Access에는 로그인에 필요한 openid, userinfo.email, userinfo.profile만 우선 사용합니다.

  4. 04

    Web OAuth Client 생성

    Clients → Create Client → Web application을 선택합니다. Authorized JavaScript origins에는 로컬과 Vercel의 origin을 넣습니다.

  5. 05

    Supabase Callback 등록

    Authorized redirect URIs에는 Supabase Google Provider 화면에 표시된 주소를 정확히 붙여 넣습니다.

    https://<PROJECT-REF>.supabase.co/auth/v1/callback
  6. 06

    Client 값을 Supabase에 입력

    생성된 Client ID와 Client Secret을 Supabase → Authentication → Providers → Google에 입력하고 Provider를 활성화합니다.

  7. 07

    앱에서 로그인 호출

    Supabase 클라이언트의 signInWithOAuth({ provider: 'google' })를 호출합니다. SSR/PKCE 앱은 앱의 callback route와 Redirect Allow List도 맞춰야 합니다.

04

ENVIRONMENT VARIABLES

환경변수 이름과 위치

.env.local
NEXT_PUBLIC_SUPABASE_URL=https://<PROJECT-REF>.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_xxxxx
Local

프로젝트 루트의 .env.local. 반드시 .gitignore에 포함합니다.

Vercel

Project → Settings → Environment Variables. 로컬과 동일한 이름으로 등록합니다.

Client 공개

NEXT_PUBLIC_ 또는 VITE_는 브라우저 번들에 노출됩니다. publishable 값만 사용합니다.

Server 비밀

sb_secret_, legacy service_role, Google Client Secret은 클라이언트 접두사를 붙이면 안 됩니다.
