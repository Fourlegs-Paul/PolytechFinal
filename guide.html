API & POSTMAN

코드보다 먼저 요청을 성공시킵니다

Postman 문서 ↗
REQUESTGET /v1/items?area=서울

URL·Method로 할 일을 정하고, Params·Headers·Body에 필요한 값을 보냅니다.

HTTP
→
RESPONSE200 application/json

Status code로 성공 여부를 확인하고 JSON의 실제 필드와 오류 메시지를 읽습니다.

Base URL

서비스 공통 주소

https://api.example.com
Endpoint

특정 기능의 경로

/v1/search
Method

조회·생성·수정·삭제

GET · POST · PATCH · DELETE
Headers

인증·데이터 형식 정보

Authorization · Content-Type
Params / Body

서버에 전달할 입력

요청 처리 결과

2xx · 4xx · 5xx
1

문서에서 계약 찾기

Base URL, endpoint, Method, 인증 방식, 필수 Params·Headers·Body, 응답 예시를 표시합니다.

2

요청 조립

Postman에서 Method와 URL을 고르고 문서대로 Authorization, Params, Headers, Body를 입력합니다.

3

Send 후 응답 읽기

2xx 성공, 4xx 요청·인증 문제, 5xx 서버 문제로 먼저 나누고 JSON 구조를 확인합니다.

4

비밀값 분리

{{base_url}}, {{api_key}}처럼 Postman 환경변수를 사용하고 공유 자료에는 실제 값을 넣지 않습니다.

5

성공 요청 저장

Collection에 저장하고 Method·URL·Header 이름·Body 형식·성공 응답을 API_CONTRACT.md에 옮깁니다.

6

앱 서버에서 재현

에이전트에게 성공한 계약을 제공해 서버 Route로 구현합니다. 비밀키를 브라우저 fetch에 넣지 않습니다.

SOCIAL LOGIN

Google OAuth 연결하기

Console 열기 ↗
1 · APP로그인 클릭
→
2 · SUPABASEGoogle로 이동
→
3 · GOOGLE사용자 동의
→
4 · CALLBACK세션 발급
  1. 01

    Cloud 프로젝트 생성

    Google Cloud Console 상단의 프로젝트 선택기에서 New Project를 선택해 프로젝트를 만들고 활성 프로젝트로 지정합니다.

  2. 02

    Google Auth Platform 시작

    Branding에서 앱 이름·지원 이메일을, Audience에서 Internal/External을 설정합니다. 수업 테스트라면 External + Test users에 본인 이메일을 등록합니다.

  3. 03

    최소 Scope 선택

    Data Access에는 로그인에 필요한 openid, userinfo.email, userinfo.profile만 우선 사용합니다.

  4. 04

    Web OAuth Client 생성

    Clients → Create Client → Web application을 선택합니다. Authorized JavaScript origins에는 로컬과 Vercel의 origin을 넣습니다.

  5. 05

    Supabase Callback 등록

    Authorized redirect URIs에는 Supabase Google Provider 화면에 표시된 주소를 정확히 붙여 넣습니다.

    https://<PROJECT-REF>.supabase.co/auth/v1/callback
  6. 06

    Client 값을 Supabase에 입력

    생성된 Client ID와 Client Secret을 Supabase → Authentication → Providers → Google에 입력하고 Provider를 활성화합니다.

  7. 07

    앱에서 로그인 호출

    Supabase 클라이언트의 signInWithOAuth({ provider: 'google' })를 호출합니다. SSR/PKCE 앱은 앱의 callback route와 Redirect Allow List도 맞춰야 합니다.

ENVIRONMENT VARIABLES

환경변수 이름과 위치

MUST DO API 키와 비밀번호 같은 실제 값은 .env.local에 저장하고, .gitignore에 등록해 GitHub 커밋과 공유 대상에서 반드시 제외합니다.
.env.local
NEXT_PUBLIC_SUPABASE_URL=https://<PROJECT-REF>.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_xxxxx
Local

프로젝트 루트의 .env.local. 반드시 .gitignore에 포함합니다.

Vercel

Project → Settings → Environment Variables. 로컬과 동일한 이름으로 등록합니다.

Client 공개

NEXT_PUBLIC_ 또는 VITE_는 브라우저 번들에 노출됩니다. publishable 값만 사용합니다.

Server 비밀

sb_secret_, legacy service_role, Google Client Secret은 클라이언트 접두사를 붙이면 안 됩니다.

LOCAL ONLY

.env.local

실제 URL·API 키·비밀번호를 저장합니다. 개인 PC에서만 사용하고 절대 Git에 추가하지 않습니다.

SUPABASE_SECRET_KEY=실제_비밀값
