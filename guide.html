1

GET과 주소 입력

Method는 GET, URL은 위의 네이버 지역 검색 주소를 붙여 넣습니다. 검색어의 공백은 Postman이 자동 인코딩합니다.

2

Params에 검색 조건

query = 성수동 파스타, display = 3을 넣습니다. URL 뒤에 같은 값이 붙는지 확인합니다.

3

Headers에 앱 인증

X-Naver-Client-Id와 X-Naver-Client-Secret 두 줄을 추가합니다. Authorization 탭은 사용하지 않습니다.

4

Send 후 200 확인

Body의 items가 배열이고 각 항목에 title·category·roadAddress가 있으면 성공입니다.

5

실패를 구체적으로 읽기

401이면 Header 이름·키를, 429이면 호출 한도를 봅니다. “안 된다” 대신 상태 코드와 오류 문구를 기록합니다.

6

서버 Route로 옮기기

앱의 /api/search?q=성수동 파스타가 네이버를 대신 호출하게 합니다. Secret은 서버의 .env.local에서만 읽습니다.

Google OAuth 연결하기

Console 열기 ↗

4 · CALLBACK세션 발급
  1. 01

    lunch-pick 프로젝트 생성

    Google Cloud Console 상단 프로젝트 선택기에서 New Project를 누르고 이름을 lunch-pick으로 지정합니다. 이후 화면 상단에 이 이름이 선택됐는지 확인합니다.

  2. 02

    학생 본인을 Test user로 추가

    Branding의 앱 이름은 “오늘뭐먹지”, Audience는 External로 설정합니다. 게시 전 테스트 단계에서는 로그인할 본인 Gmail을 Test users에 넣습니다.

  3. 03

    최소 Scope 선택

    Data Access에는 로그인에 필요한 openid, userinfo.email, userinfo.profile만 우선 사용합니다.

  4. 04

    Web OAuth Client 생성

    Clients → Create Client → Web application을 선택합니다. 이름은 lunch-pick web, Authorized JavaScript origins는 http://localhost:3000과 https://lunch-pick.vercel.app입니다.

  5. 05

    Supabase Callback 등록

    Authorized redirect URIs에는 Supabase Google Provider 화면에 표시된 주소를 정확히 붙여 넣습니다.

    https://<PROJECT-REF>.supabase.co/auth/v1/callback
  6. 06

    Client 값을 Supabase에 입력

    생성된 Client ID와 Client Secret을 Supabase → Authentication → Providers → Google에 입력하고 Provider를 활성화합니다.

  7. 07

    앱에서 로그인 호출

    Supabase 클라이언트의 signInWithOAuth({ provider: 'google' })를 호출합니다. SSR/PKCE 앱은 앱의 callback route와 Redirect Allow List도 맞춰야 합니다.
